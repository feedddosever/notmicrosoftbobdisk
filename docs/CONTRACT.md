# SheetShift shared contract

The single source of truth for the workbook layout, the build/ map, the service interface
Bob implements, and the harness entry points. Machine-readable layout: `sheetshift.json`.
Author: Claude Code (AI agent) — scaffold; see ATTRIBUTION.md. Changes need a person's review.

All data is synthetic. The carrier is **Example Mutual Insurance Co. (FICTIONAL)**.

## 1. Workbook `workbook/example_mutual_ho3_rater.xlsx`

Generated by `python -m tools.gen_workbook --n 40 --seed 2026` (byte-deterministic;
hashes in `workbook/SHA256SUMS`). Sheets, in order:

| Sheet | Layout |
|---|---|
| `Policies` | Row 1 = the 14 input names (A..N). Rows 2..41 = 40 policies, one per row. |
| `RateTables` | A1 = FICTIONAL banner. Lookup tables and 13 defined names (section 1.3). |
| `Calc` | 43 formula columns A..AQ. Row 1 = canonical output names. Rows 2..41; Calc row r reads Policies row r. |
| `Summary` | A1 = FICTIONAL banner. A2..A6 labels, B2..B6 whole-book aggregates. |
| `About` | A1 = FICTIONAL banner; carrier, generator command, disclosure that anomalies were seeded. |

**Banner choice.** The banner text is "FICTIONAL — all names, rates and rules invented for a
software demonstration". `Policies!A1` and `Calc!A1` must stay headers (row layout is fixed), so
there the banner is a **cell comment** on A1; `RateTables!A1`, `Summary!A1` and `About!A1` carry it
as text. `About` is the last sheet, so sheet positions 1-4 are unchanged. Tools must address sheets
by name (from `sheetshift.json`), never by index.

## 2. Value conventions

- **Service input:** `policy` dict with the 14 input names; blanks are `None`; `effective_date` is
  a `datetime.date`.
- **Service output:** a dict with every one of the 43 output names. Numbers are `int`/`float`,
  dates are `datetime.date`, text is `str`. An error is either an
  object with attribute `.code` (for example `"#N/A"`) or a `str` starting with `"#"`.
- **Comparison tolerance (plan §6.3):** numbers within absolute 1e-6; dates exact; text exact and
  case-sensitive; errors by code; blank, 0 and "" are different.
- **JSON encodings in build/:** numbers and text as-is, blank `null`, dates `{"date": "YYYY-MM-DD"}`,
  errors `{"error": "#N/A"}` (`build/workbook_values.json`). In markdown briefs errors are bare
  (`#N/A`), text is quoted, blanks are `blank`.

## 3. build/ (generated by `make map` = `python -m tools.dump_workbook --expect-lints 3`)

Deterministic and committed; CI runs `make map && git diff --exit-code build/`. `build/cache/` is
ignored. LibreOffice is needed only when `build/workbook_values.json` is stale.

| File | Content |
|---|---|
| `graph.json` | `columns`: 43 entries in column order, each `{col, cell ("Calc!O"), output_name, rows [2,41], n_cells, template_r1c1, template_a1 (row 2), precedents (output names), precedent_cols (letters), inputs (input names), tables [{operand, ref, name}], named_ranges, functions, exceptions (cells), manual_rule, topo_index, unit}`; `cells`: 5 Summary cells `{cell, label, formula, template_r1c1, precedents, ...}`; `topo_order` (43 output names); `rule_order` (48 rule keys); `named_ranges`; `exceptions` [{id, type, cell}]; `inputs`; `function_inventory`; `unsupported` (volatile functions, macros, ...; empty here); `limits`; `stats`; `workbook_sha256`. |
| `units.json` | `{"U1": {columns, outputs, inputs, upstream, cells, range, lints}, ... "U4"}` |
| `lints.json` | `{workbook_sha256, count, lints: [{id, type, sheet, column, output_name, cell, cells, row, formula, column_rule, manual_rule, options, status, ...}]}`; exactly A1..A3 |
| `rate_tables.json` | `{workbook_sha256, tables: {name or literal ref: {ref, header, rows[, literal_refs]}}, scalars: {CreditCap, MinPremium, AssessRate, HurrCapPct}}` extracted from the workbook |
| `workbook_values.json` | The 40 rows of Calc values from LibreOffice forced recalc, keyed by workbook sha256 |
| `sheets/Calc.md` | The 43 column rules (< 15,000 chars) |
| `sheets/Calc_exceptions.md` | A1..A3 and the unsupported-construct scan |
| `units/U1.md`..`U4.md` | One brief per unit: rules, reads, open lints, 5 sample rows (< 5,000 chars each) |

Units (contiguous in topological order): **U1** A..J · **U2** K..T · **U3** U..AD · **U4** AE..AQ.
A unit reads only policy inputs `p`, its own earlier columns, and outputs of earlier units `c`.

## 4. Service interface (written by IBM Bob)

- Package `service.sheetshift_ho3`; `service.sheetshift_ho3.rater.quote(policy: dict) -> dict`
  as in section 2. `rater.py` keeps `ORDER` as a literal tuple equal to `graph.json` `topo_order`
  and never reads `build/` at runtime.
- One function per column, `c_<col>_<output_name>(p, c)`, decorated
  `@covers("Calc!<col>", "<output_name>")` from `service.sheetshift_ho3.xlsem`, which also exposes
  `STEPS`: a list of `{cell, name, fn, file, line}`. `fn` is the function **name**
  (`f.__name__`), `file` the repo-relative path with forward slashes, `line` the `@covers` line.
  The harness resolves `fn` to the loaded function by name and file (`harness.common.service_steps`);
  a callable in `fn` is also accepted. Each Calc column is tagged exactly once.
- `xlsem.XLError(code)`: an `Exception` with `.code`; the unit smoke passes upstream error values
  into unit functions as `XLError` instances.
- Units live in `service/sheetshift_ho3/units/uN_<desc>.py` (N = 1..4); the unit smoke
  (`harness.smoke --unit UN`) imports that file alone and calls each tagged function as `fn(p, c)`,
  with the upstream outputs `c` taken from the oracle, so a unit can be checked before `rater.py` exists.
- Tables: `service/sheetshift_ho3/data/rate_tables.json`, a byte copy of `build/rate_tables.json`.

## 7. Site DOM contract (for IBM Bob's `public/verify.js` and `public/trace.js`, task T10)

Page shells, `public/app.css` and `public/site.js` are written by Claude Code; Bob writes only
`public/verify.js` and `public/trace.js`. Each shell already loads its script with
`<script src="verify.js" defer>` / `<script src="trace.js" defer>`, after `site.js`.

**Constraints.** Each page sets a Content-Security-Policy: scripts, styles and `fetch` are
same-origin only (`/api/...` and `data/*.json`), and inline `<script>`, inline event handlers
(`onclick=`) and `style="..."` attributes are blocked (setting `element.style.x` from JS is fine).
No frameworks, no external requests. Scripts must render text with `textContent`, not `innerHTML`.
Use existing classes from `app.css` (`card`, `notice warn|bad|info`, `empty`, `table-wrap`, `badge
green|red|warn|decided|neutral`, `status-line`, `kv`, `num`, `mono`). When `site.js` finds that a
script is missing it shows `#verify-pending` / `#trace-pending`; the scripts need not touch these.

**Optional helpers** on `window.SheetShift` (from `site.js`, loaded first): `loadJSON(name)` →
Promise of `data/<name>` parsed or `null`; `el(tag, attrs, children)`; `fmtInt(n)`;
`fmtPct(x, digits)`; `githubUrl(site, path, line)` → `<repo_url>/blob/<commit>/<path>#L<line>` or
`null`; `linkOr(url, text)`; `empty(msg)`. `data/site.json` has `repo_url` (may be `null`),
`commit`, `mode` (`"live"` or `"static"`) and `service.standin`.
